# quantum-adapter library: design

Date: 2026-10-16. Status: draft for review.

## 1. Goal

A PyPI library, `quantum-adapter`, that fine-tunes Hugging Face language models with
adapters whose weights are generated by quantum circuits. Other developers will depend on it,
so it must be correct, well tested, documented, and honest about where it helps.

This is deliverable 1 of 3. The Studio UI (2) and the Hugging Face release (3) get their own
specs and use only this library's public API.

### Production-usefulness rule

A method ships as **stable** in a release only if, on the release benchmark (section 7), it meets
all of these against LoRA rank 4 on the same model, data and budget:

| Criterion | Threshold |
|---|---|
| Accuracy | within 1.0 point of LoRA, mean of 3 seeds, on at least 2 tasks |
| Trainable parameters | at least 5x fewer than LoRA |
| Training time | at most 2x LoRA |
| Inference after merge | same speed as the base model (no extra ops) |
| Beats same-size classical adapter | yes, on both tasks (shows the circuit structure helps) |

Known before the benchmark: `tensor` cannot meet the parameter criterion on GPT-2-sized layers
(section 4.3), so it will ship as experimental. A method that fails is listed as experimental: using it requires `experimental=True` in the config
and emits a warning. Methods that fail badly are dropped. If no method passes, the release stops and
the results are reviewed before anything is published.
The docs publish the numbers either way, including losses.

## 2. Prior work used

| Method in library | Source | What we take |
|---|---|---|
| `amplitude` | our experiment; related to QPA-style generation | circuit amplitudes become LoRA-shaped factors A, B |
| `unitary` | Quantum-PEFT, ICLR 2025, arXiv 2503.05431 | ΔW = U Λ Vᵀ; U, V from RY + CZ circuits |
| `tensor` | QuanTA, arXiv 2406.00132 | hidden axes treated as qudits; trainable tensors on axis pairs; `T − S` neutral init |

QTHA (arXiv 2503.12790) is cited as related work; no public code or circuit details, so not implemented.
All methods are implemented independently from the papers' descriptions and cited in the docs,
README and model cards.

Only `amplitude` and `unitary` use genuine quantum gates and support Qiskit export. `tensor` is
quantum-inspired (non-unitary gates) and is labelled so.

## 3. Public API

```python
from quantum_adapter import QuantumAdapterConfig, get_quantum_model, QuantumModel

config = QuantumAdapterConfig(
    method="amplitude",          # "amplitude" | "unitary" | "tensor"
    target_modules=["c_attn"],   # names or regex, like PEFT
    rank=4,                      # amplitude / unitary
    qubits="auto",               # amplitude: fewest qubits giving enough amplitudes
    depth=10,                    # circuit layers
    entanglement="ring",         # "ring" | "line" | "full"
    modules_to_save=["score"],   # extra layers to train and save, e.g. a classification head
)
model = get_quantum_model(base_model, config)   # freezes base, adds adapters
model.print_trainable_parameters()
model.circuit_summary()                         # qubits, dials, gates per layer vs LoRA
model.save_pretrained("out")                    # adapter_config.json + adapter_model.safetensors
model = QuantumModel.from_pretrained(base_model, "out")
model.push_to_hub("user/name")
merged = model.merge_and_unload()               # plain transformers model
circuits = model.export_circuits()              # Qiskit QuantumCircuit per layer (extra: [qiskit])
```

Works with the Hugging Face `Trainer` and plain PyTorch loops (the wrapper is an `nn.Module`).
API names mirror PEFT so it can be proposed upstream later.

## 4. Methods

### 4.1 `amplitude` (tested: SST-2 84.8% with 3,228 params vs LoRA 87.6% with 148,992)
- Per target layer: an n-qubit RealAmplitudes-style circuit (RY layers + CNOT entanglement), n = auto.
  Unlike Qiskit's RealAmplitudes it omits the closing RY layer and keeps the last CNOT layer; that layer
  is a fixed permutation of the amplitudes, so the reachable weights are the same up to a fixed reordering.
- State vector of 2ⁿ real amplitudes, first r·(in+out) entries reshaped to A (in×r), B (r×out).
- Update: x·A·B·s, trainable angles θ and a scale s that multiplies B only.
- Neutral start: s starts at 0, so the adapter is exactly zero at step 0; s gets a gradient at step 0
  and θ from step 1. This is the tested setup (84.8%). Scaling A and B together gives zero gradient
  at 0 and never learns; a unit test pins this.

### 4.2 `unitary` (Quantum-PEFT)
- ΔW = U Λ Vᵀ, U ∈ ℝ^{in×r}, V ∈ ℝ^{out×r} with orthonormal columns, Λ a trainable r×r diagonal.
- U and V are the first r columns of orthogonal matrices produced by RY + CZ circuits on
  ⌈log₂ d⌉ qubits, depth L. Each of the L blocks is one RY layer followed by a CZ entangler, and a
  closing RY layer follows the last block, so each factor has (L+1)·⌈log₂ d⌉ angles (`theta_u` and
  `theta_v` have shape (depth+1, qubits)). The paper quotes about (2L+1)·log₂ d per factor for its own
  layer layout; v1 keeps the simpler (L+1) layout because it is the one tested and benchmarked, and
  the saved-adapter format (`format_version: 1` in `adapter_config.json`) fixes it.
- Non-power-of-two dims (e.g. 768): v1 uses the next power of two and takes the first d rows, then
  re-orthonormalizes with a QR step. Documented as a deviation from the paper's Shannon decomposition.
- Λ initialised to 0 (neutral start; U, V still receive gradient through Λ once it moves; checked by test).

### 4.3 `tensor` (QuanTA)
- Factor the hidden size d = d₁·…·d_N with N = `tensor_axes` (default 4), factors as close to equal as
  possible, e.g. 768 = 6·4·4·8 and 2304 = 6·8·6·8.
- On GPT-2-sized layers it trains about as many numbers as LoRA rank 4 (13,024 against 12,288 on
  GPT-2's `c_attn`), so it cannot meet the at-least-5x-fewer-parameters rule of section 1 and will be
  experimental whatever its accuracy. It is kept for comparison.
- Trainable general tensors on each axis pair, applied in sequence; y = W₀x + 𝒯θx − 𝒮x with 𝒮 a frozen copy.
- Supports square and rectangular layers by factoring input and output separately.

## 5. Internal structure

```
quantum_adapter/
  config.py        QuantumAdapterConfig (dataclass, JSON round-trip, validation)
  sim/             batched real statevector simulator: RY, CNOT, CZ; exact autograd
  methods/         amplitude.py, unitary.py, tensor.py: each maps params -> ΔW or (A, B)
  layers.py        AdapterLayer wrapping nn.Linear and transformers Conv1D
  model.py         QuantumModel: target matching, freezing, save/load, merge, hub
  export.py        Qiskit export (optional dependency)
```
Each unit is testable alone. Methods share one interface: `delta(params) -> (A, B)` or a callable
applying ΔW to x, plus `merge_weight()`.

Performance: the simulator runs on CPU by default (35x faster than Apple MPS for 14 qubits, measured);
the circuit is evaluated once per optimizer step, not per token, and results are moved to the model's device.

## 6. Errors

Clear messages, raised at `get_quantum_model` time:
- not enough amplitudes for the requested rank and qubits, with the minimum qubits needed;
- no modules matched `target_modules`, listing available names;
- estimated simulator memory above a limit (default 20 qubits / 8 GB), with how to reduce it;
- unsupported layer type, naming the type;
- loading an adapter saved for a different base model shape.

## 7. Testing and benchmarks

Unit tests (every push):
- simulator vs hand-computed states; norm = 1; matches Qiskit's statevector simulator on random circuits;
- gradients vs finite differences, for every method;
- neutral start: adapted model output equals base model output exactly at step 0;
- every trainable parameter has a non-zero gradient after one step (catches the B·scale bug class);
- learns: loss drops on a tiny synthetic task within 20 steps;
- save → load → identical logits; merge → logits equal within 1e-5;
- `nn.Linear` and `Conv1D` layers; tiny GPT-2 and tiny Llama configs (no downloads in CI);
- CPU always; MPS and CUDA when available.

CI: GitHub Actions, Linux / macOS / Windows, Python 3.10–3.13.

Release benchmark (manual, before each release; results committed to `results/`):
- tasks: three. SST-2 (2-class sentiment, `nyu-mll/glue`) and AG News (4-class news topic, `fancyzhx/ag_news`,
  longer texts, 2,000-example fixed test subset), and E2E text generation (`GEM/e2e_nlg`, parquet conversion;
  GPT-2 `LMHeadModel`, prompt `"{meaning_representation} => "`, loss on the target only; greedy decoding,
  40 new tokens, stop at EOS or newline; first 500 unique test meaning representations with all their
  references; metric corpus BLEU via `sacrebleu`, stored as BLEU/100 so the 1-point rule is 0.01 for every task;
  the `head` baseline is the frozen pretrained model);
- contenders: head only, LoRA r=4 (via `peft`), each method, and a same-size classical control:
  for `amplitude` and `unitary`, a fixed random projection with the same trainable count; for `tensor`,
  whose count is close to LoRA's, LoRA at the rank with the nearest parameter count;
- LR picked on a dev split; 3 seeds; report mean and range, params, train time, merged inference time;
- release blocked if a stable method regresses by more than 1 point.

## 8. Packaging and release

- `pyproject.toml`, hatchling build, `uv` for development; deps: torch ≥ 2.3 (float16 LayerNorm on CPU is missing in older torch), transformers, safetensors,
  huggingface_hub; extra `[qiskit]`.
- Apache-2.0 licence; type hints; changelog; semantic versioning; first release 0.1.0 (beta).
- Public GitHub repo; docs: quick start, API reference, "how it works", benchmark results, citations.
- Publishing through PyPI Trusted Publishing from a GitHub release; every release first to TestPyPI,
  installed in a clean venv, quick start run, then PyPI.

## 9. Out of scope for v1

Low-bit quantization of the dials (Quantum-PEFT §4: a unitary adapter is already ~1 KB, so no real gain); vision and multimodal models; models above ~1B parameters; training on real quantum hardware;
official PEFT integration; Studio UI and Hugging Face release (own specs).
